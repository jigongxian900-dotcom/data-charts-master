# 见数配色体系

色彩先表达关系，再建立气质。原始令牌在 [color-system.json](../assets/color-system.json)，HTML、SVG和PPTX共用同一份选定颜色。主题只是候选；用户指定品牌、现有成品或对比语义时，以当前任务为准。

## 七套候选色系

| 主题 | 视觉特征 | 优先场景 |
|---|---|---|
| 墨海·珊瑚 `tidal` | 暖纸、深墨、蓝绿与陶红对照 | 编辑式经营分析、增减与贡献 |
| 霁蓝·琥珀 `cobalt` | 冷白、明确蓝色、少量暖焦点 | 精确比较、技术数据、投屏 |
| 松绿·陶土 `grove` | 低饱和绿、暖土色、柔和层次 | 时间序列、持续运营、供应链 |
| 梅紫·青瓷 `iris` | 梅紫主线、青瓷对照 | 分布、区间、多组科研数据 |
| 夜航·流光 `nocturne` | 深海底、浅色文字、亮色数据 | 屏幕探索；打印另取浅底稳定态 |
| 石墨·印刷 `graphite` | 明度、轮廓、直接标签 | 无彩色检查与印刷；不可只靠灰色区分类别 |
| 石榴红 `ruby` | 石榴红、暖白、墨色，青瓷作对比 | 经营分析、目标对比与重点标注；颜色本身不代表好坏 |

不把某主题绑定某国家或行业。同一报告默认一套主题；章节切深浅底可以，但同一对象的颜色语义不能反转。

## 用法

- `accent` 是焦点，`accent2` 是第二比较对象。两者本身不表示好坏。
- `positive/negative` 表示有利/不利。先确认方向：成本下降可能有利，缺陷率上涨可能不利。仅表示增减时用明确正负标签与发散两端，不能暗示绩效判断。
- `categorical` 用于离散类别。固定类别到颜色的映射，筛选后不重新编号换色。超过可辨范围，改小多图或分组，不无限轮换同色。
- `sequential` 表示有序数量，低到高的明度递进。标出范围与单位；缺失用空白、斜线或“缺失”，不能套最低值色。
- `diverging` 围绕已说明的中点。目标、同比零点和行业基准各是不同语义，不能把均值当自然零点。
- 同一图中，非重点对象用低饱和色、细线或浅填充。降低强调程度不能把真实小值删掉。
- 图表直接标签配合颜色。重要曲线加线型或点形；选中对象同时改变轮廓/标记/文字状态。特别检查红绿色觉差异与灰度情境。

## 颜色与数量分开

面积、长度、坐标和带宽必须由数值决定。渐变仅改变材质或表示连续强弱，不制造第二个未说明的数据维度。不用透明叠加后的颜色误导面积或数量。

浅色块可用深色边界与直接标签保障阅读，不要求每个浅色填充都达到文字对比度。普通文字以4.5:1、大字以3:1作检查线；关键图形边界以3:1作检查线。检查需使用实际相邻背景，色板表中的通过不代表实际成图通过。

## 可运行入口

基础六类图助手可读取输入的 `theme`，或显式传入：

```powershell
uv run --no-project python scripts/chart_html.py build chart-spec.json --out report.html --theme tidal
```

选择不改变数据、几何和口径。新图谱提供七主题现场切换；旧版六主题交付保持原样。用于观察同一图在不同观看条件下的效果，不替代业务数据的逐图验收。

石榴红以 `#A51D36` 为重点，暖纸 `#FBF8F5`、正文 `#30262D`、青瓷 `#287C82` 为配合。避免整页大面积亮红；多类别仍使用明确不同色相。红色不自动表示不利，正向/不利分别用独立状态色与文字，不能让品牌色和判断状态混成同一个角色。没有使用Logo/IP时，不额外引入资产或把页面变成品牌海报。
