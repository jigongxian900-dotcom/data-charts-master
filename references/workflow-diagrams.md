# 见数流程图入口

[交互样例](../examples/workflow/index.html) 使用 [费用申请源模型](../examples/workflow/source.json)。此入口随见数一起使用，按同一份模型生成决策图、责任泳道图以及可核查的实际路径。

```powershell
uv run --no-project python scripts/workflow_diagram.py spec.json --out workflow.html
```

成品可离线打开。可在当前结构和风格下导出独立 SVG。导出使用最后选定的稳定状态。图形与标签分别为 SVG 几何和文本。HTML 的可操作图层留在 HTML，PPTX 按所承诺的编辑层另行验证。

## 先选读法

| 读者要回答 | 表达与检查 |
|---|---|
| 通过哪个条件后去下一步 | 决策图。起点、条件、两个结果和回返都要读得出。 |
| 接手前需要谁做完什么 | 责任泳道。位置表示承担者，跨泳道连接核对交接条件。 |
| 哪些状态可以往返 | 状态图。写清事件、守卫条件、初始与退出。若状态本身与参与者不同，用状态作为主对象。 |
| 谁在什么时候通知谁 | 时序图，参与者分列，事件顺序纵向可读。 |
| 多少人或货真实走哪条路 | 在规则图上叠加完整已知路径，或按需要另设数量流图。以稳定 ID 或分组路径证明连线。 |
| 组件之间依赖什么 | 结构图用接口、方向和边界表达。避免用先后位置暗示时间。 |

原生构建器针对前两种结构和已知实际路径。状态、时序、架构等按本节推导后在见数内用独立 SVG 或 HTML 编排，使用实物验证几何、标签和动效。

## 模型字段

- `title`、`purpose` 和 `source` 为可核查信息。先说明读者要做什么和来源。
- `roles` 为 1–5 个唯一名称。每个 `node` 有 `id`、`label`、`role`、`kind`、`stage`、`track`。`kind` 支持入口、动作、判断、终点。每个节点在决策图和泳道图都要有独立位置。把跨越多列、密集同列或长边标注的流程拆成子图，检查各段衔接。
- 每个 `edge` 指向已声明节点。判断节点至少有两个不同条件，每个普通动作只有一个下一步。回返可以出现，追加原因。规则图先验证路径可达，再检查箭头与重叠。
- 可选 `observations` 为互不重叠的路径组，声明 `period`、`unit` 和各组 `nodes`、`count`、`state`。每组从入口开始，逐边真实可连接。未结路径到最后已知节点为止。先证实记录互斥与覆盖范围。重复经过一条边时，边上计经过该边的记录数，每笔仅计一次。
- 可选 `focus_node` 定义需要追查的对象，从经该节点的实际记录重算本次读数。总线和其他节点保持位置。数字读作经过某边的申请数，线宽用于区分规则与当前聚焦。

## 场景与动效

- **纸面编辑** 用扁平细线、墨色和一处酒红焦点，适合正文、长图与审阅稿。
- **审阅蓝图** 用冷白、钢蓝和清楚的责任分带，适合讨论责任交接。
- **深色投影** 用炭黑图面与暖琥珀焦点，适合会议投屏。另验投影实际尺寸与灰度打印。

先显现规则，再按已知记录绘制路径，边读数在终态出现。快速切换从可见状态接续；减少动态时直接显示终态。打印和 SVG 导出核对最终布局。参考 [Lieflat Diagrams](https://github.com/larashero3-dotcom/lieflat-diagrams) 的路径显现与可达呈现、[Diagram Design](https://github.com/cathrynlavery/diagram-design) 的结构取舍与不同媒介的视觉变体。本示例的模型、制图、视觉和运行逻辑在见数内部实现。
