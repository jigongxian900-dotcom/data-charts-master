# 流程图与数据图表分工

见数以原生 [流程图入口](workflow-diagrams.md) 处理纯流程、决策、泳道与真实路径。先判断读者主要要执行规则还是核对数据；混合问法共用节点和路径 ID，把规则、角色与观察对齐到同一模型。

| 读者问什么 | 主要产物 | 核对什么 |
|---|---|---|
| 这一单下一步找谁、满足什么条件、失败怎么回退？ | 流程图或泳道图 | 起点和终点、触发、动作、责任人、分支条件、兜底、回路。条件互斥时检查覆盖。责任未知不猜。 |
| 实际多少件到达、在哪个节点等待、哪条路径流失最多？ | 数据图、分组差额或有真实路径的流图 | 时间窗、观察对象、分母、可连接的记录 ID、去重、等待状态、守恒。没有稳定 ID 或完整路径时保留阶段或边际，不补完整走法。 |
| 想看规则和实际是否一致？ | 同一页双读法。先保持规则拓扑，再查看实际记录。 | 规则中允许的边不会自动成为已观察边。异常路径需要独立标识。只共享节点 ID、标签和视觉语义，数据与假设要各自可核对。 |

流程动效可以按入口、判断分支和结果逐步显现。文字覆盖、方向和责任要在稳定结果中可读。定量流向的宽度、计数和颜色才遵循数据。两类出图可以沿用一次选定的字体、底色、强调色及减少动态策略。各输出保留自身的 SVG、HTML 或可编辑源。

[费用申请流程图](../examples/workflow/index.html) 可切决策、泳道、实绩与三种风格。另有 [规则与实绩动效组合](../examples/motion-composition/index.html#routes)。两个样例均使用固定合成数据。正式 BPMN 定义按 [OMG 规范](https://www.omg.org/spec/BPMN/2.0.2/) 或用户现有标准。执行部门另有口径时使用其流程契约。
