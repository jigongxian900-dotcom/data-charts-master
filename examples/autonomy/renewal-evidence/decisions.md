# 制作取舍与复查记录

## 判断与行动边界

- 不画营销经理要求的流转。事件次数不是唯一客户数，阶段独立计数，付费及续订还可能属于旧批次；没有客户ID、时间链或来源去向。流转守恒、同批转化和漏斗包含关系均不成立。
- 不计算10月试用到付费转化率。不能用payment事件数除trial事件数替代客户转化；本页没有展示这类伪比率。
- 建议先对Comet做客户成功排查试点。成熟的2026-08-01初次付费批次中，12/40按期续订（30%），28人未按期；Atlas为72/100（72%），同样28人未按期；Beacon为64/80（80%），16人未按期。率与人数共同判断，未把低率直接等同全部资源优先级。
- 40人是有限的单批次样本。不做统计显著性或产品质量因果断言；需要客户名单和原因字段才能实际联系客户。试点以核对原因、服务工时、触达与逾期追回为先。追回与原到期指标分开。

## 表达取舍

主图采用共享0–100%尺度的水平点/线轨道，同一行标注率、分子/分母及未按期人数。三行顺序沿原产品顺序保持稳定。红褐色表示建议试点对象，非“已验证服务收益”。直接标签无需悬停。

只画简单率图，而不画桑基、漏斗、流向或额外事件柱。事件原值在全量表中，避免把相邻事件长度暗示成客户流失。按期率条形为可行备选，但单率不足以表达样本量与可行动人数；主图把它们邻近对齐。没有额外复杂表达所需的数据收益。

桌面SVG使用共同刻度与右侧数值列；手机SVG逐产品重排，保留大字号、分子分母、截止日、批次、来源与解释。表格在手机可左右滑动，页面本体不溢出。网页图、SVG文件、下载SVG与computed使用相同派生数据与chart函数。

## 覆盖、空值与成熟性

- 输入：3产品，12条事件，9条批次；无记录删除。3条成熟批次参加续订率，6条未成熟批次全部保留。
- 已到期分母为eligible_n，只使用完整到期批次；按期续订只使用对应renewed_by_due_n。没有平均产品比率。
- 未成熟批次的renewed_by_due_n原始空白保留为null，表中显示“空白（未知）”；eligible_n=0仍为原值，不把它误读为批次无人。
- 未成熟批次规模：Atlas250人、Beacon210人、Comet130人；提前续订6、5、4人单列，均未混入成熟率。
- “未按期续订”不是永久客户流失，也不是已查明的服务失败。

## 补采与复查

补采客户/账户ID、产品ID、唯一事件ID、事件时间、首次试用批次、首次激活定义及时间、首次付费时间、订阅/支付ID、续订归属ID与应续订日期；明确跨产品、重复试用、退款与观察窗口处理。再以10月开始试用的同批唯一客户为分母，以约定窗口内首次成功付费的同批唯一客户为分子。

客户成功负责人先取得Comet这28名客户的可核对名单，再记录到期触达、产品使用、原因、服务工时和后续续订。2026-11-30批次完整到期后逐产品复查按期续订人数/已到期人数，保留样本量；12月批次继续未成熟。服务净效果需可比对照或随机分组；不把前后变化写成干预因果。

## 重建

在本目录执行：

```powershell
uv run --no-project python producer.py
```

可加`--skill-root`指向所读候选Skill根目录，重建前核对其指纹。输出HTML离线自包含；源CSV、题设、计算JSON与SVG亦单独保留。checksums.json列本交付目录除自身外全部文件指纹。完成后冻结，不自评分。
