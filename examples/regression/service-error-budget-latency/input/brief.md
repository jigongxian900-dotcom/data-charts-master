# B05 · 在线服务的错误预算与慢请求

本题数据全部为原创合成数据。它不代表任何真实组织。

## 工作问题

值班主管要判断先处理哪个服务与区域，以及是否需要回滚发布。请比较请求量、错误预算消耗和延迟分布，定位短时异常与持续问题。要能选取异常时段，联动查看同一服务的区域及延迟桶，再切换度量保持对象可识别。明确发布记录能证明和不能证明什么。

## 数据定义

- 每行是1分钟×区域×服务。requests 为完成请求数，errors 为其中失败请求数。
- latency_counts 是全体完成请求的互斥延迟桶计数，总和必须等于 requests。
- 桶为[0,100]、(100,250]、(250,500]、(500,1000]、(1000,+∞)，单位毫秒。
- 99%请求成功为窗口SLO。错误预算为请求数乘1%。消耗倍数为实际错误数除允许错误数。
- 可从桶计数定位分位数所在桶，不能从该数据得到桶内精确分位数。
- release 的 minute 是发布开始标记，不是已证实事故起点。

## 证据边界

未提供链路追踪、控制实验和资源监控。发布与异常的时间相邻不能直接证明因果。不得平均各行错误率代替总体错误率。

## 交付与操作

请自主选择表达方式。不得询问评委想要哪一种图。
交付可运行的分析页面、源数据下载和使用说明。
页面要让负责人从总体判断进入具体对象，再回到总体。
请支持桌面、手机、键盘和触摸操作。
要能筛选、聚焦、比较、复原和导出当前状态。
空结果要解释原因，并保留恢复入口。
连续切换时，页面必须保留正确的对象与当前状态。
请让有分析价值的状态变化可追踪。尊重运行时 reduced-motion 设置。
导出和打印必须对应一个完整、已稳定的状态。
不得用装饰动画代替业务分析。可以说明某项动画不适用的原因。
