# B04 · 招聘等待与在途负荷

本题数据全部为原创合成数据。它不代表任何真实组织。

## 工作问题

招聘负责人要分配下月的两位协调员。请同时判断在途积压、已投入工时和申请后拿到首份offer的累计机会。批次观察长度不同，拒绝和退出后不再有本次申请的offer机会。比较团队与来源时保留这些边界。能从一组申请切到某位候选人，再改变申请批次范围并找回该候选人。

## 数据定义

- 一行是一次申请，candidate_id 唯一。day 均为从 origin 起算的日数。
- terminal_type 的 offer、rejected、withdrawn 互斥。terminal_day 为空表示截至快照仍在途。
- screened_day、interviewed_day 是实际发生日。空值表示未发生，不能补成0。
- 观察年龄为 snapshot_day 减 applied_day。
- recruiter_hours 为截至快照累计已投入工时，不是剩余工作量。
- 估计等待机会时，仍在途属于右删失。拒绝与退出属于竞争结局，不能按普通在途处理。

## 证据边界

未提供岗位难度、招聘质量、入职后表现或未来处理产能。不得把来源差异写成来源因果效果。未成熟批次不能按最终完成率排名。

## 交付与操作

请自主选择表达方式。不得询问评委想要哪一种图。
交付可运行的分析页面、源数据下载和使用说明。
页面要让负责人从总体判断进入具体对象，再回到总体。
请支持桌面、手机、键盘和触摸操作。
要能筛选、聚焦、比较、复原和导出当前状态。
空结果要解释原因，并保留恢复入口。
连续切换时，页面必须保留正确的对象与当前状态。
请让有分析价值的状态变化可追踪。尊重运行时 reduced-motion 设置。
导出和打印必须对应一个完整、已稳定的状态。
不得用装饰动画代替业务分析。可以说明某项动画不适用的原因。
